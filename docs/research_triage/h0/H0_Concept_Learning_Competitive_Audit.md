# H0 — Concept-Learning and Persistent-Revision Competitive Audit

**Audit:** LASTPAPER-H0-20261031  
**Search cutoff:** 2026-10-31  
**Question:** Is human-grounded structural credit assignment plus persistent schema revision already present under another name?

## Competitor comparison

“Target known” means the human or protocol tells the method which concept/value to correct. “Persistent” means the correction affects later instances; it does not imply that the underlying ontology changes.

### Industrial anomaly-detection threats

- **HITL Memory Correction** [P17] directly changes PatchCore memory from binary feedback and reuses updated memory on future examples. Its annotations are simulated from dataset ground truth; it is not evidence of a real operator protocol. It closes generic binary-feedback persistent-memory claims.
- **DPB-DF** [P16] filters local patches and adds them to an evolving defect bank using coarse defect labels. It closes generic local attribution + online defect-bank claims, with richer target labels than binary feedback.
- **WeakREST** [P18] learns local block/pixel anomaly scores from weak image, box, or block supervision. It closes generic weak image-label-to-localization claims, but does not establish persistent schema revision.
- Local N0 audits classify EISCA broad patch responsibility and SCAEA broad decision-aware querying as HOLD: narrow binary-only update-target identification and exact future state-value prediction remain UNKNOWN, not established novelty. [P19]

## Adversarial equivalence tests

The proposed contribution is “just CB2M” if it receives a correction to a known concept value, stores the feature representation plus that correction, and replays it for similar future inputs.

It is “ordinary Bayesian mixture learning” if its structural credit is a posterior over a fixed set of latent components, with a standard likelihood and prior, and selecting the highest-posterior component is sufficient. Calling the latent component a schema does not change the inference problem.

It is “concept bottleneck correction” if the ontology is fixed, a user identifies a wrong concept value, and the method only propagates that correction to the current prediction. Interactive CBMs and concept realignment already cover cost-sensitive querying and relation-aware value correction.

It is “continual concept learning” if it only appends dimensions or retains previously learned concept/class mappings. iCSN, CONCIL, Res-CBM, CLG-CBM, and the Dynamic-V2C project page already cover concept creation, expansion, or retention in different settings.

It is “memory retrieval under another name” if the method does not revise a rule’s applicability or relations and its future gain disappears after matching feature, context, memory capacity, and feedback cost against nearest-neighbor, prototype, CB2M, and rule-dictionary baselines.

It is “standard VOI” if an observation is selected by expected risk reduction minus annotation/action cost. A future-utility objective can be placed inside a sequential Bayesian decision model; added state variables or AIF/EFE terminology do not alone establish a new principle.

## Residual novelty boundary

The one potentially distinct problem is **identifying which reusable, human-grounded schema object and scope should change when the same or similar visual evidence admits competing interpretations, then testing whether that scope revision transfers to held-out instances and contexts**. None of the audited works clearly demonstrates that exact industrial feedback protocol.

That absence is not proof of novelty. iCSN already revises and adds human-interactive concepts; CB2M already persists corrections; concept-incremental methods already expand vocabularies; theory revision already changes rules; causal concept graphs already encode relations. The proposed residual must beat a combined but simple baseline that receives identical human labels and context.

No theorem, learning objective, human annotation set, or empirical result in the current project demonstrates that distinction. Until a tiny expert annotation pilot shows that the structural target is identifiable and that a simple context-keyed memory/rule baseline fails, the contribution should be treated as **HYPOTHESIS / UNKNOWN**, not novel.

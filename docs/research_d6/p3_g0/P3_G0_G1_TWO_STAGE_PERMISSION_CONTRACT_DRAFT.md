## 前置输入冻结

先完成 identity-only 资格表、产品分区、代表层名单及待授权特征阶段的 stress 规则，记录 manifest、代码、特征、H12 和五个既有 X 锚点的 SHA。所有数据仅作开发用途，D-conf 不参与。开发历史有曝光；同 sample-key 或可识别近重复不可跨角色。对于权限缺口或未解析的单件独立性，只能按后续明确授权的条件使用，不能转成通过。

冻结原 H 的零 logit 属性判定、X 的 5 个纠正锚（2 正/3 负）和锚点标签，四臂均同信息、同锚、同头、同硬类别覆盖：

| 臂 | 锚选择与距离 | 附加门 |
|---|---|---|
| G | G-Mean 单位向量 `(1−cos)/2` | 无 |
| G+C | 同 G | `abs(H logit) <=` 截至相应冻结时间的既有 X 查询揭示前 `abs(logit)` 中位数 |
| L | `0.5×G + 0.5×` 双向 4×4 局部格最近距离 | 无 |
| L+C | 同 L | 同 G+C |
| Never Reuse | 不选择或不复用 | 必须逐项等于 H |

局部格按原网格位置和有效 patch mask 构造，每非空格单位 token 平均并归一化；局部距离为两个方向各自等权最近格距离平均再等权平均。空格或零范数格忽略；无可用格则该视角局部读出 BLOCK，不能静默替换方法。检索距离 tie 按最早锚事件、再按不透明 ID。阈值和置信门均含等号。

## Stage A：Prediction，独立进程

白名单仅包括已批准身份 manifest、后续另获许可的图像/冻结特征、冻结 H12、5 个 X 锚及标签、公式/固定门、已封存的 D-cal 阈值。不得读取 D-eval 属性标签、source defect type、mask 内容或 evaluator truth，也不能访问其他受保护集。执行分两个受控批次：

1. 用冻结模型和无标签规则生成全部 D-cal 的 H、四臂必要连续分数/距离/门信息及 Never Reuse 候选；完成后不可覆盖地写出并封存，记录清单、代码、数据、特征与预测 SHA。
2. 经独立 D-cal 阈值流程生成并封存阈值后，Stage A 使用该阈值对 D-eval 产生完全一致字段的最终输出并封存；禁止访问 D-eval 标签。两个批次均不得使用未来缺陷类型或 truth 选择锚点。

输出最小字段：不透明 image ID、产品/组、checkpoint、H 连续 score 和二元预测、各臂锚点 ID/事件序号/符号、全局/局部距离、阈值与门控判定、未复用原因、覆写类别、数据/特征/代码 SHA 和 seal。只在受控私有目录保留行级字段。

## D-cal 阈值封存

D-cal 全部无标签预测先封存；独立校准进程再读取 D-cal 四态人工标签，只用有二元真值的两个完整产品，U/N-A 排除。对每个距离/门组合的阈值分别按有限预测距离的所有不同断点及 never-reuse 点求组内等权、产品等权的修复率和损害率。预先冻结目标：**在产品等权损害率 ≤0.05 的可定义候选中，最大化产品等权修复率；并列先取更小损害率、再取更小距离阈值；若无正修复候选，选 never-reuse。** Never-reuse 的阈值编码为专用枚举，不以负无穷参与数值比较。

阈值目标的正/负分母按 H 原错/原对、各产品分别计算；任一 D-cal 产品缺该目标必要的原错或原对二元组时，该目标 **BLOCK**，不得临时改变目标或把缺失率补零。先验检查产品是否同时有 Present/Absent；缺类时属性 BA/FPR/FNR 对应目标也 BLOCK。不能读取 D-eval 标签或按事后曲线重选阈值；校准结果、支持数、tie-break、输入 seal 和阈值以不可覆盖方式封存。

## Stage B：Evaluator，独立进程

先验证 D-cal、阈值、D-eval Stage A 的 seal，以及身份 manifest、代码和特征 SHA 的依赖关系；任何不一致阻断评价。仅在通过后读取已授权 D-eval 人工标签。按每视角其自身四态评价，以组内等权后产品等权汇总 Repair/Harm、属性 FPR/FNR、BA 和覆盖率；报告每产品、组、支持与缺失，不把两个视角算独立物件。无相应正负或 H 对错分母时报告 NA。标签不得返回预测进程；评价后的可达曲线只作事后描述，不能重新写入阈值或称部署表现。

四臂是硬标签覆盖，原 H 连续 score 不变。AP/AUROC 基于 H 的原分数，**不能将 AP/AUROC 改善归因于没有连续修正分数的记忆臂**。Never Reuse 逐项预测必须等于 H，且整个输出顺序和身份保持一致。

## 真正的隔离负控

用合成 identity/feature/label fixture 在隔离目录运行 Stage A 与 Stage B：先冻结预测文件并记录逐字节 SHA；修改 evaluator 的合成真值使至少一个二元类别翻转，重新运行 **Stage B**，验证至少一个预设指标确实变化；再核对 Stage A 原文件 SHA 和预测字节完全不变，且预测进程无法打开 truth fixture。也应覆盖 Never Reuse 全项等于 H、跨组排除、空锚回退、U/N-A 不为 0、seal 篡改阻断和未知阈值阻断。不能把上一轮检查脚本里创建但没有用于重算评价的置换数组当作通过本项负控。
